# コミット作成

## 手順

1. `git status` で変更ファイル一覧を確認する。
2. `git diff`（未ステージ）と `git diff --cached`（ステージ済み）で内容を確認する。
   まだ何もステージされていない場合、ユーザーが対象を指定していなければ
   関連する変更をどこまで含めるか確認する。
3. `git log --oneline -10` などで直近のコミットメッセージのスタイルを確認し、
   このリポジトリの慣習と明らかに異なる場合はそちらに合わせる。
4. 変更内容から Conventional Commits の type を選ぶ:
   - `feat`: 新機能
   - `fix`: バグ修正
   - `refactor`: 挙動を変えない構造変更
   - `docs`: ドキュメントのみ
   - `chore`: 雑務（設定変更、依存更新など）
   - `test`: テストの追加/修正
5. コミットメッセージを日本語で作成する。
   - 件名: `type: 内容`（50字程度、体言止めまたは命令形）
   - 本文: 必要なら空行の後に「なぜ」その変更をしたかを箇条書きで書く。
     「何をしたか」はdiffから自明なので書かない。
   - 例:
     ```
     feat: PR作成手順をgit-opsスキルに追加

     - gh CLIでのPR作成をユーザー確認込みで自動化するため
     ```
6. **メッセージ案をユーザーに提示し、承認を得てから** `git commit -m "..."` を実行する。
7. 秘密情報（`.env`、`credentials.json`、APIキーらしき文字列など）が含まれていないか
   diffを確認する。含まれていればステージから外すか、ユーザーに警告して判断を仰ぐ。

## 注意

- コミットを分割すべき複数の意図が混ざっている場合（例: 機能追加とフォーマット変更が
  同居している）は、分割コミットを提案する。ただしユーザーが「まとめてコミットして」
  と言っている場合はそれに従う。
- 空コミットは作らない。

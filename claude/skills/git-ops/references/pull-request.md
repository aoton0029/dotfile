# PR作成・更新（gh CLI）

`gh` コマンドが使えることを前提とする。使えない場合はユーザーにインストール/認証
（`gh auth login`）を案内する。

## 新規作成

1. 現在のブランチの状態を確認する:
   - `git status`（未コミット変更がないか）
   - リモート追跡ブランチの有無、必要ならpushが要ることを確認する
2. ベースブランチとの差分全体を把握する:
   - `git log <base>...HEAD`（PRに含まれるコミット全体。直近のコミットだけを見ない）
   - `git diff <base>...HEAD`
3. タイトルと本文の案を作る:
   - タイトル: 70字以内、日本語で内容を簡潔に
   - 本文: 以下の構成を基本とする
     ```
     ## Summary
     - 変更点を1〜3個の箇条書きで

     ## Test plan
     - [ ] 動作確認方法をチェックリストで
     ```
4. **push・PR作成前に** ブランチ名／タイトル／本文案をユーザーに提示し、承認を得る。
5. 承認後に実行する:
   ```
   git push -u origin <branch>
   gh pr create --title "<title>" --body "<body>"
   ```

## 更新

- PR本文の更新: `gh pr edit <number> --body "<new-body>"`
  （実行前に新しい本文案を提示して確認を取る）
- 既存のレビューコメントを確認したい場合:
  `gh api repos/{owner}/{repo}/pulls/{number}/comments`
- レビューコメントへの返信や解消は、内容を要約してユーザーに提示し、
  対応方針を確認してから行う。

## 注意

- draft PRにするかどうか、レビュアー指定が必要かどうかは、指定がなければユーザーに確認する。
- force-push が必要になる操作（PRブランチの巻き戻しなど）は、ユーザーが明示的に
  指示した場合のみ行う。

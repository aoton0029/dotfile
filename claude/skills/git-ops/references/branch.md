# ブランチ操作

## 手順

1. `git status` で未コミットの変更がないか確認する。ある場合、新しいブランチに
   持ち越したいのか、コミットしてから切るのかをユーザーに確認する
   （持ち越し自体は git のデフォルト挙動なので黙って進めてよいが、意図しない
   ファイルが混ざっていないかは確認する）。
2. `git branch -a` や `git log --oneline --all -20` などで既存のブランチ名の
   傾向を確認し、命名規則があればそれに合わせる。特に慣習が見当たらない場合は
   以下を既定として提案する:
   - `feat/xxx`: 新機能
   - `fix/xxx`: バグ修正
   - `chore/xxx`: 雑務
3. ブランチ名の案をユーザーに提示し、承認を得てから作成する:
   ```
   git checkout -b <branch-name>
   ```
4. 作業ベースが古い可能性がある場合（例: `main` が更新されている）、
   `git log <base>..HEAD` や `git log HEAD..<base>` で乖離を確認し、
   必要であればユーザーに fetch/pull や統合方法（merge/rebase）を確認する。
   ただし rebase の実行自体はこのスキルのスコープ外なので、実行が必要な場合は
   ユーザーに委ねる。

## 注意

- ブランチの削除（`git branch -d/-D`）は、ユーザーが明示的に指示した場合のみ行う。
- リモート追跡ブランチの強制上書きにつながる操作は行わない。

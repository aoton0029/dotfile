# git操作を代行する

コミット・ブランチ・PRまわりの定型作業を、毎回ゼロから判断するのではなく
一貫した手順で行うためのスキル。対象はどのリポジトリでもよく、そのリポジトリ
固有の慣習があればそちらを優先する。

## いつ使うか

「コミットして」「変更を保存して」「ブランチを切って」「PRを作って」
「PRの説明を更新して」など、git のコミット/ブランチ/PR操作に関する依頼で使う。

## 共通方針

- 作業対象リポジトリの **既存のコミット履歴** (`git log`) を最初に確認する。
  規約がこのスキルの既定（Conventional Commits・日本語）と明らかに違う場合は、
  リポジトリ側の慣習に合わせる。
- `git status` を必ず先に確認し、意図しない変更や untracked ファイルを
  巻き込まない。`git add -A` / `git add .` は使わず、対象ファイルを個別に指定する。
- commit・push・ブランチ作成・PR作成/更新など **状態を変更する操作は、実行前に
  内容（コミットメッセージ案、PRタイトル/本文案など）を提示してユーザーの確認を
  得てから実行する**。確認なしに連続実行しない。
- 何か想定外の状態（コンフリクト、未知のブランチ、大量の未コミット変更など）に
  気づいたら、判断を先取りせずユーザーに報告する。

## 手順フロー

やりたいことに応じて参照ドキュメントを読む。

- コミットを作りたい → [references/commit.md](references/commit.md)
- ブランチを作成/切り替えたい → [references/branch.md](references/branch.md)
- PRを作成/更新したい → [references/pull-request.md](references/pull-request.md)

## やらないこと

- `--force` push、`git reset --hard`、`--no-verify` などの危険操作は、
  ユーザーが明示的に指示しない限り行わない。
- 既存コミットの書き換え（`commit --amend`、rebase）はこのスキルのスコープ外。
  必要な場合はユーザーに確認する。
- ユーザーが指定していない範囲のファイルまで勝手にステージングしない。
- コミット/PRの内容に `.env` や認証情報らしきファイルが含まれていないか確認し、
  含まれていれば実行前に警告する。

# 薄いカードを育てる

capture は「浅くても残す」ためのスキル。このスキルはその逆で、**1枚を選んで深くする**。
一度に何枚も触らない。

## 前提を読む

- [../knowledge-capture/references/vault.md](../knowledge-capture/references/vault.md)
- [../knowledge-capture/references/card-format.md](../knowledge-capture/references/card-format.md)

## 起動のされ方

- `/knowledge-deepen` — 引数なし。薄いカードを提示して選ばせる
- `/knowledge-deepen <ノート名orテーマ>` — 対象を直接指定
- 「hearsay を検証して」等の依頼文

`--vault <path>` を付けると、その回だけ Vault の場所を上書きできる（vault.md の解決順を参照）。
残りの引数は対象の指定として扱う。

## 手順

### 1. 対象を選ぶ

テーマ指定があればそれを使う。無ければ `knowledge/` の frontmatter を
（サブフォルダを含めて再帰的に）走査して候補を出す:

- `confidence: hearsay` のもの（作業キューの本体。`updated` が古い順）
- 「検証していないこと」が空、または「根本メカニズム」が数行しかないもの
- リンク（`[[...]]`）が1つも無い孤立カード

候補を3〜5枚出し、`AskUserQuestion` で1枚選ばせる。

### 2. どこが薄いかを言う

選んだカードを読み、**欠けている節を名指しする**。
「因果が用語の列挙になっている」「具体例が原理と対応していない」「トレードオフが無い」など。
全部を一度に埋めようとせず、一番効く欠落から手を付ける。

### 3. 掘り下げる

- **hearsay の検証** — 一次情報（公式ドキュメント、仕様、論文、実際に動かす）で裏を取る。
  裏が取れなければ「検証していないこと」にその旨を書き、confidence は据え置く
- **因果を伸ばす** — 「Aだから B」の1段で止まっているところを、
  何が何に作用してその性質が生まれるかまで分解する
- **関連を張る** — 似た概念・前提概念・応用先を `[[...]]` で結ぶ。
  対応するカードがまだ無くてもリンクは書いてよい（次に書くべきカードの印になる）
- **反例と限界** — 原理が成り立たない条件を「原理から導けること」に足す

### 4. 更新する

- 本文を書き換え、`updated` を今日の日付に
- `summary` が実態とずれていれば直す
- **confidence の昇格は人間に確認してから。AI が `verified` を付けない。**
  検証の根拠（何を読んだ／何を動かした）を `sources` と「検証していないこと」に残す

### 5. 報告

何が薄かったか → 何を足したか → まだ残る未検証、の3点だけ簡潔に。

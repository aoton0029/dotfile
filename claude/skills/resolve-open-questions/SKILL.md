# 未確定事項を一問ずつ潰す

ドキュメントの穴を埋める作業は、まとめて「これとこれとこれ、どうしますか？」と聞かれると
ユーザーは答える気力を失う。逆に一問ずつ、具体的な選択肢つきで、文脈が見えている状態で
聞かれればほぼ即答できる。このスキルはその「即答できる形」に分解するためのもの。

## 手順

### 1. 対象ファイルを確定する

ユーザーが明示していればそれ。していなければ、直前の会話や作業中のファイルから推測して
一つ挙げ、「これで合っていますか」と確認する。複数ファイルを渡された場合は一つずつ順に
処理する。並行に進めると文脈が混ざって答えにくくなる。

### 2. ファイルを読み、見出し構造に沿って未確定事項を抽出する

ファイル全体を読む。grep でマーカーだけ拾うのでは足りない（下の4つ目が落ちる）。
見出し（Markdown の `#`、YAML のトップレベルキー、コードのセクションコメントなど、
そのファイルなりの構造単位）を骨格として、その配下にある未確定事項を拾う。

拾う対象:

- **明示マーカー**: `TBD`, `TODO`, `FIXME`, `未定`, `要検討`, `要確認`, `後で決める`, `???`, `XXX`, `未決事項`
- **空欄・プレースホルダ**: 見出しだけあって中身がない、`<...>`, `xxx`, `（記入）`, `N/A?`
- **両論併記**: 「AまたはB」「AにするかBにするか」のように決めきっていない記述
- **暗黙の穴**: 他のセクションには書かれている項目が、そこだけ抜けている（例: 他のホストには
  IPが書いてあるのに一台だけ空欄）。これは検索では見つからないので、同種のセクション同士を
  見比べて気づくこと

見出しが一つも無いファイル（ベタ書きのテキスト等）なら、その旨を伝えたうえで論理的な塊で
区切る提案をするか、区切らず抽出だけして進めてよいか確認する。

### 3. 抽出結果を一覧で見せる

質問を始める前に、見つけた項目を番号付きで提示する。全体像が見えていると、ユーザーは
「3番は今日決めなくていい」「5番はもう決まっていて書き忘れ」といった間引きができる。

```
以下 N 件の未確定事項が見つかりました:

1. [## ネットワーク構成] VLAN分割 — 「要検討」のまま
2. [## バックアップ] 保存世代数 — TBD
3. [## 監視] アラート通知先 — 見出しのみで中身なし
4. [## ストレージ] ファイルシステム — 「ext4かXFS」で両論併記

上から順に伺います。飛ばしたいものがあれば言ってください。
```

### 4. AskUserQuestion で一問ずつ聞く

**一回の呼び出しにつき一項目**。AskUserQuestion は4問までまとめられるが、ここでは意図的に
一つに絞る。前の回答が次の質問の選択肢を変えることが多いためだ。「VLANを分ける」と決まった
なら次に聞くべきはセグメント設計だが、「分けない」ならその質問自体が消える。まとめて聞くと
的外れな選択肢を並べることになる。

質問の作り方:

- **header**: 項目名を12文字以内で（例: `VLAN分割`, `保存世代`）
- **question**: 該当箇所の現状（元の記述の引用）を含めて、何を決めるのかを一文で
- **options**: そのファイルの他の部分・既存の慣習・一般的なベストプラクティスから導いた、
  **そのまま本文に書き込める具体値**を2〜4個。「はい/いいえ」「決める/決めない」のような
  中身のない選択肢は、結局そのあと自由記述で聞き直すことになるので作らない
- 推奨がある場合は先頭に置き、ラベル末尾に `(推奨)` を付け、description に理由を書く
- description には、その選択を取った場合にファイルがどう書き換わるかが分かる情報を入れる

選択肢を作れないほど情報が足りない項目（ユーザーの環境固有の値、実測しないと分からない数値
など）は、AskUserQuestion を使わず普通に質問する。無理に選択肢をでっち上げない。

### 5. 回答をその場で反映する

一問答えてもらったら、**次の質問に進む前に** Edit で書き換える。理由は二つ。途中で中断されても
成果が残ること、そして反映後の記述が次の質問の文脈になることだ。

書き換え方:

- **マーカーは消して、決定内容で置き換える**。取り消し線を引いたり「✅決定済み」を付けたりして
  古い記述を残さない。ドキュメントは「今の正」を表すものであり、旧記述が残ると読む人が毎回
  「どれが有効なのか」を判断する羽目になる。決定内容を、本来そこに書かれるべき自然な文章・値
  として書く

### 6. 全項目終了後にまとめる

- 決めた項目と決定内容の一覧
- 飛ばした項目（残った未確定事項）
- 反映の過程で新たに気づいた未確定事項があれば提示し、続けるか確認する

## やらないこと

- **勝手に決めない**。「たぶんこうだろう」で埋めるのが一番危険で、しかも埋まってしまうと
  誰も再検討しない。判断材料が無い項目は未確定のまま残し、その旨を報告する方がよい
- **一気に全部聞かない**。まとめて聞かれた質問は、まとめて放置される
- **ついでに構成をいじらない**。見出しの整理やリライトは別の作業。ユーザーが頼んでいない限り、
  触るのは未確定箇所と決定ログだけにとどめる

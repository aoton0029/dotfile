# プロジェクト規約に従って実装する

同じプロジェクトでも、実装のたびに「どの層に書くか」「docstring はどう書くか」がぶれる。
ぶれた結果 view に業務ロジックが溜まり、API から同じ処理を呼べなくなって複製が起きる。

このスキルの狙いは規約文書を綺麗に作ることではなく、**書き始める前に置き場所を決めさせ、
書き終わったあとに照合させる**こと。判断を人間の記憶ではなくファイルに固定する。

## 手順

### 1. 規約を読む

対象プロジェクトの以下を探して読む。

- `docs/CONVENTIONS.md` — 規約の実体（これが主）
- `docs/ARCHITECTURE.md` — あれば層構成の補足として
- `CLAUDE.md` — 規約へのポインタや、規約より優先されるプロジェクト固有の指示

見つかったら次へ。**無ければ 2 へ**。

規約とユーザーの今回の指示が食い違う場合は、ユーザーの指示が勝つ。ただし黙って
逸脱せず「規約では X ですが、今回はご指示どおり Y にします」と一言添える。
規約が古くなっているだけかもしれないので、更新するか確認する。

### 2. 規約が無ければ立ち上げる

規約ファイルの新規作成は `conventions-init` スキルが担当する。**そちらを呼ぶ**
（`/conventions-init <プロジェクト名/概要>`）。AskUserQuestion で決めごとを選ばせ、
同梱テンプレートから `docs/CONVENTIONS.md` を起こしてくれる。

規約はこの先ずっと効き続けるファイルなので、その場で勝手に生成せず、
必ずユーザーに確認を取る流れに乗せる。ここで合意していないと毎回の実装がずれ続ける。

ユーザーが「今は規約作りまで手を広げたくない」と言うなら、規約無しで進めてよい。
その場合は既存コードの実態（構成・命名・docstring の書式）に合わせ、
新しい流儀を持ち込まない。

テンプレートの本体はこのスキルが持っている:

- `assets/base-conventions.md` — スタック非依存のベース
- `assets/flask-conventions.md` — Flask 拡張サンプル
- 新しいスタック用の拡張を書き足すときは `references/authoring.md` を読む

### 3. 書く前に置き場所を決める

実装に着手する前に、今回書く処理を1つずつ規約の「配置判断表」に当てて、
どのディレクトリのどのファイルに置くかを決める。数行でよいので明示する。

```
- 入力フォーム定義      → app/forms/user_form.py
- 登録処理（業務判断）  → app/services/user_service.py
- 画面ルーティング      → app/views/user_view.py（薄く）
- パスワードハッシュ    → app/utils/security.py（汎用）
```

これを先にやるのは、書きながら決めると必ず「今いるファイル」に書いてしまうから。
view を編集中に業務ロジックを思いつけば view に書く——それが層の崩壊の起点になる。

既存の似た処理が既にあるなら、新規に作らずそれを再利用・拡張する。
規約は「どこに置くか」だけでなく「重複を作らない」ためのものでもある。

### 4. 規約どおりに書く

規約の命名・docstring 書式・層ごとの責務に従う。特に効いてくるのは:

- **入口（view / api / controller）は薄く**。認可 → 入力検証 → service 呼び出し →
  描画またはシリアライズ、だけ。DB クエリと業務判断を書かない。
  薄くしておくと、同じ service を画面からも API からも呼べる。
- **service を厚く**。業務ルール・トランザクション・複数モデルにまたがる操作はここ。
- **汎用処理は utils へ**。特定の業務を知らない処理（日付整形、ハッシュ、ファイル名正規化）は
  service に置かず utils に切り出す。service から業務知識のない部品を分離しておくと
  テストが軽くなる。
- **docstring は規約の書式で**。書式が揃っていないと、後から読む人も AI も
  引数の意味を本文から推測する羽目になる。

### 5. 書いたあとに照合する

変更・追加したファイルについて、規約の「セルフチェック」節を1項目ずつ当てる。
記憶で「たぶん守った」と済ませず、実際にファイルを見て確認する。

逸脱が見つかったら直す。直せない逸脱（既存コードとの整合上どうしても崩れる等）は
黙って残さず、何がどう外れているかをユーザーに報告する。

## 同梱ファイル

- `assets/base-conventions.md` — スタック非依存のベース規約テンプレート。
  見出し構成が固定されており、拡張はこの見出しを上書き／追記する
- `assets/flask-conventions.md` — Flask 向け拡張サンプル（Flask-Login / Flask-WTF /
  Flask-SQLAlchemy / Flask-CORS 構成）。他スタックの拡張を書くときの手本にもなる
- `references/authoring.md` — 新しいスタック用の拡張を書き足す手順。手順 2 で
  対応する拡張が無かったときに読む

## 関連スキル

- `conventions-init` — 規約ファイルを対話で新規作成する側。手順2 の実行役
